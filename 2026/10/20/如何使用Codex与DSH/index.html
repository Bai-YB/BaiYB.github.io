如何使用 Codex 与 DSH：从安装到接入 GPT、DeepSeek

发表于2026-10-20|更新于2026-10-20|实用教程
|总字数:5.9k|阅读时长:18分钟|浏览量:

想让 AI 帮忙改代码、整理资料、处理文件，结果还没开始干活，先被账号、API Key、模型供应商绕晕了？

别急，这些名字看着热闹，真正需要你操作的地方并不多。这篇文章就沿着我的实际配置过程，把 ChatGPT 注册、Codex 安装、CC Switch 配置，以及 DSH Desktop 接入模型 串起来。能点按钮解决的地方，咱们就先不和命令行较劲。

📌 开工前看一眼

  • 注册 ChatGPT、访问 OpenAI 官方登录页前，请先确认自己能够正常访问相关网站。
  • 只想使用 DSH + DeepSeek，可以直接跳到 DSH 部分，不必先把前面的账号都注册一遍。
  • 本文截图来自 2026 年 10 月的界面。按钮位置可能会变，认准名称即可；赠金、分组倍率与可用模型以你操作当天的页面为准。

先认人：Codex、DSH、CC Switch 分别干什么？

Codex 是 OpenAI 的智能体工具，可以结合项目和本地文件处理任务，例如阅读代码、修改文件、运行检查。本文主要使用它的桌面界面，不要求你先学会终端命令。

DSH 是 DeepSeek Harness 的简称，同样可以围绕工作区处理任务。本文选用的是社区维护的 DSH Desktop，它把 DSH 做成了方便下载安装的图形客户端，支持配置模型和扩展插件。项目介绍可以查看 DSH Desktop 网站 和 项目仓库。

CC Switch 则负责管理 Codex 等工具的模型连接配置。你可以给 Codex 准备一套 GPT 配置，再准备一套 DeepSeek 配置，需要哪个就切过去。

记住这一点，后面会轻松很多：客户端负责让你操作，模型负责处理请求，API Key 是调用模型的凭证。

围绕这两款客户端，本文会演示下面几种常用搭配：

你想用什么 配置路线
Codex + GPT 系列模型 安装 Codex → 获取中转站 Key → 用 CC Switch 导入
Codex + DeepSeek 安装 Codex → 获取 DeepSeek 官方 Key → 在 CC Switch 选择预设
DSH + DeepSeek 安装 DSH Desktop → 使用客户端提供的 DeepSeek 登录或 Key 入口
DSH + GPT 系列模型 安装 DSH Desktop → 在模型设置中添加中转站

**不用四条路线全部做一遍。**先选自己最想用的一条，跑通之后再折腾其他的。

按需跳转：注册 ChatGPT · 下载 Codex · 准备中转站 Key · 配置 CC Switch · 安装 DSH · DSH 接入 GPT · 常见问题

一、注册 ChatGPT：先把账号准备好

已经有 ChatGPT 账号的朋友，可以跳过这一节。

1. 打开官网，点击免费注册

访问 ChatGPT 官网，点击右上角的 免费注册。

在注册窗口里，选择自己方便的方式。页面可能提供邮箱、Google、Apple 等选项，具体以实际显示为准。

这里我用 邮箱注册 演示，准备一个能正常收邮件的邮箱就好。

2. 按提示完成验证

输入邮箱后，跟随页面完成验证和账号资料填写。如果要求设置密码，就设置一个单独使用的密码；如果收到验证码，就回邮箱查收。

完成后，进入自己的账号界面：

💡 记住你是怎么登录的。

如果注册时选择了 Google，后面也优先通过 Google 登录。隔几天再回来，别一顿操作给自己“喜提第二个账号”。

网页版适合日常聊天。如果你希望 AI 结合电脑上的项目、文件继续工作，接下来就可以安装桌面客户端。

不同客户端的表现还会受到模型、上下文和功能设置影响。**换个客户端，并不能保证回答质量自动升级。**我们这里选择桌面端，主要是为了更方便地处理实际任务。

二、下载 Codex：Mac 和 Windows 分开看

打开 Codex 官方介绍页，从页面进入适合自己系统的下载入口。

关于名字的小变化

本文沿用大家熟悉的“Codex 桌面端”说法。当前 OpenAI 官方快速开始 将桌面入口称为 ChatGPT 桌面应用，并说明可以在其中进入 Codex 模式。因此，看到 ChatGPT 名称也别急着怀疑自己下错了，先检查是否来自官方入口、应用里能否进入 Codex。

Mac 用户

按官网提供的方式下载。拿到 .dmg 安装包后，打开并按照提示安装；如果需要选择芯片架构，注意区分 Apple Silicon 和 Intel。

Windows 用户

本文截图中的 Windows 下载流程会进入 Microsoft Store / 微软应用商店。官网给你的下载入口或小型安装程序，也可能继续调用商店完成安装。

到下面这个页面后，点击 下载 / 安装 / 获取，等待安装结束即可。截图里因为已经装好，所以按钮显示为“打开”。

如果商店打不开、下载一直转圈，可以先检查系统网络、商店登录状态和地区设置。如果你正使用代理，也可以尝试让微软商店直连后重试；这是一条排查办法，不代表所有网络环境都必须关闭代理。

第一次打开，先认识两个登录入口

安装完成后打开应用，可以看到：

入口 怎么理解
继续登录 使用 ChatGPT 账号完成官方登录，后续可用功能与额度取决于账号情况
使用其他方式登录 进入 API Key 等其他认证入口；本文接下来主要配置 API 模型来源

这里不需要急着往输入框里粘东西。先把 API Key 和供应商配置准备好，再回来完成对应入口。

如果你的账号被要求进行额外验证，请按官方页面提示处理；不能把某个账号遇到的手机号验证，当成所有账号都必经的一步。官方登录方式说明

三、准备模型来源：中转站和官方 API 都可以

给客户端接入模型时，最常用到三样东西：

配置项 是什么 例子
API 地址 请求发到哪里 https://api.baiyb.top/v1
API Key 用什么凭证调用 从你自己的平台账号创建并复制
模型 ID 具体调用哪个模型 gpt-6.1-sol，前提是对应平台确实开放了它

本文会演示两种来源：我的中转站，以及 DeepSeek 官方开放平台。

中转站提供统一的模型接入入口；选择中转站后，模型请求会经过它，费用也按对应站点规则计算。你也可以直接使用支持的模型厂商 API。

**先把账本分开：**ChatGPT 订阅、中转站余额、DeepSeek 官方余额是三回事。给其中一个充值，另外两个的余额不会跟着增加。

1. 注册中转站账号

这里介绍一下我自己的站点：汇枢Flow。本文的 GPT 系列模型接入就以它为例，分组和价格都可以在站内查看。

🎁 给读者留个体验入口

注册后可以微信联系我，领取 5 美元测试额度。具体领取条件和活动是否仍在进行，以我当时确认的信息为准。先跑通、体验一下，再决定后续怎么用，doge。

打开网站，点击 开始使用，按页面提示注册并登录。

2. 创建自己的 API Key

进入控制台后，点击左侧的 API 密钥。有些版本会把它叫作“令牌管理”，意思相近。

点击右上角的 创建 API 密钥，进入下面的表单：

可以这样填：

  1. 名称：起一个自己看得懂的名字，例如 Codex-电脑 或 DSH-日常使用。
  2. 分组：按准备调用的模型选择。使用 GPT / Codex 路线时，选择站内对应的 Codex 分组。
  3. 额度与有效期：按自己的需要设置，并确认令牌没有过期、没有把目标模型限制掉。
  4. 点击 保存更改，然后复制创建好的完整 Key。

截图里，codex_nx 显示为 0.22x；codex_限时特价 显示为 0.1x。后者是限时福利分组，不保证一直开放。按本文截图操作时，可以优先考虑 codex_nx；实际选择前，还是看一眼当前分组说明和模型价格。

倍率也不等于每次请求的固定费用，最终消费以站内计价和账单为准。

🔑 API Key 当成“能花余额的钥匙”保管。

不要发进群聊、放进公开仓库，也别让它原样出现在教程截图里。需要的是“模型调用 Key”，不要误拿个人设置中的账户管理令牌。两个都叫令牌，但岗位不同。

拿到 Key 后先放好，下一步请 CC Switch 出场。

四、安装 CC Switch，让 Codex 换模型更方便

1. 下载并安装

打开 CC Switch 项目官网，选择对应系统的版本。

  • Windows：通常选择 .msi 安装包；便携版先完整解压，再运行程序。
  • Mac：按页面提供的安装方式操作，并留意芯片架构说明。
  • 在 GitHub 下载时，请认准 farion1231/cc-switch，不要把源码压缩包当安装包。

2. 认准 Codex，添加供应商

打开 CC Switch 后，左侧这一列是它支持管理的不同工具。本文先点击 Codex，再点击 添加供应商。

这里最容易点错的地方，就是还停在 Claude Code 页面，却给它添加了一套原本打算交给 Codex 的配置。先看一眼应用名称，省得配完才发现走错片场。

在添加页中，你会看到很多供应商预设：

有厂商预设就优先用预设；接入自己的中转地址时，再用自定义配置或站内导入。

下面两种路线按需选择，不需要都完成。

路线 A：给 Codex 接入 DeepSeek 官方 API

第一步：选择 DeepSeek 预设

在“模型厂商”中选择 DeepSeek，进入配置页。

预设通常会准备好 API 地址和相关配置。点击右侧的 获取 API Key，进入 DeepSeek 官方开放平台。

第二步：在官方平台创建 Key

登录后进入 API keys 页面，点击 创建 API key。同时确认账号有可用余额；如果没有赠金或余额，再按需要充值。

创建完成后，立即复制并妥善保存完整 Key。页面也提示了：完整密钥只在创建时显示，关闭后不能指望它再出来跟你打招呼。

第三步：回到 CC Switch 保存

  1. 把刚才的 Key 粘贴到 API Key 输入框。
  2. 保留 DeepSeek 预设的 API 地址与协议设置。
  3. 查看模型列表，点击 获取模型列表 并选择要用的模型；如果预设已经有模型项，核对后保留即可。至少确认有一个可用模型。
  4. 点击右下角的 添加。

模型名称可能更新，不必死抄旧截图。以当前预设和 DeepSeek 官方 API 文档 为准。

如果供应商卡片显示 需要路由，还要在 Codex 的“路由”页面启动本地路由，并将请求路由到该供应商。普通原生直连预设则按它的默认方式使用。跟随当前预设，不要为了“看起来更高级”把每个开关都打开。

路线 B：通过中转站给 Codex 接入 GPT

第一步：在密钥菜单中选择 CC Switch

回到中转站的 API 密钥 页面，找到刚才创建、分组也选对的那一行，点击右侧的 三个点，选择 CC Switch。

注意，这里选择的是 API Key 对应行的菜单，不是去管理后台添加“上游渠道”。普通用户用自己的 Key 配客户端即可。

第二步：选择 Codex 和主模型

在弹出的导入窗口中：

  1. 应用选择 Codex。
  2. 填写一个容易识别的配置名称，例如 汇枢Flow-GPT。
  3. 主模型选择 gpt-6.1-sol。
  4. 点击 打开 CC Switch，按浏览器提示打开应用，并在应用内确认导入。

如果列表里没有 gpt-6.1-sol，先检查令牌分组和当前可用模型，或联系站点确认。教程里写了它，不代表所有分组都会自动拥有它。

**没有一键导入菜单怎么办？**在 CC Switch 里选择 Codex → 添加供应商 → 自定义配置，手动填写对应信息即可：

字段 本站 GPT 接入示例
名称 汇枢Flow-GPT，可自行命名
API 请求地址 https://api.baiyb.top/v1，如站内给出专用地址则按站内说明
API Key 自己在本站创建的模型 Key
模型 gpt-6.1-sol，需要该令牌确实有调用权限
上游格式 Responses（原生），适用于本站对应的 Responses 线路

第三步：启用配置，完全退出再重开

导入完成后，回到 CC Switch 的 Codex 页面，找到对应供应商卡片，点击 启用 / 切换。截图中的入口是卡片右侧的三角形按钮，启用后会显示 使用中。

⚠️ 这一条值得单独记住：切完供应商，完全退出 Codex，再重新打开。

  • Mac：使用应用菜单退出，或按 Command + Q。
  • Windows：关闭窗口后，如果托盘里还有应用图标，再右键选择退出；没有托盘图标时，通过应用菜单完成退出即可。

“把窗口关了”和“程序已经退出”，有时候真是两码事。模型列表没更新时，先别急着和 Key 较劲。

3. 回到 Codex，完成登录并测试

供应商启用后重新打开桌面客户端，让它读取新的配置。如果仍停在登录页，先确认 CC Switch 中该供应商处于“使用中”、客户端也确实已经重启，再通过 使用其他方式登录 按当前版本提示继续。API 地址和模型配置以刚启用的供应商为准，进入主界面后确认选择了 Codex 模式。

如果你希望同时保留官方账号身份和依赖它的功能，可以查看 CC Switch 设置中的 Codex 应用增强 → 直连切换时保留官方登录。不同版本的入口位置略有变化。仅使用本地 API 工作流时，不必为了接入中转站特意折腾这个选项。

验证时做两件事：

  1. 在新聊天里发送一句简单的问题，确认模型正常返回。
  2. 打开对应平台的使用日志，检查刚才的调用时间和模型是否对应。

只看客户端显示的账号名称，不能判断费用到底记在哪边。中转站配置就看中转站日志，DeepSeek 官方配置就看官方用量。

到这里，Codex 这条路线就配好了。下面换 DSH Desktop——它的模型配置入口在客户端里面，步骤会更集中。

五、安装 DSH Desktop：先用 DeepSeek 跑起来

1. 下载并完成首次引导

打开 DSH Desktop 项目网站，下载对应系统的版本并安装。

当前网站可能展示 DSH Desktop 或 DSH Next 等名称，按项目当时提供的版本说明选择即可。本文使用桌面客户端的图形界面流程，无需先搭建命令行环境。

首次打开后，跟随应用内引导熟悉界面：

2. 登录 DeepSeek，留意账号赠金

如果引导里提供 登录 DeepSeek，可以按提示完成登录。如果你更习惯使用 API Key，也可以选择客户端提供的 Key 配置方式。

本文截图左下角显示，账号领到了一笔 6 元新手赠金，并标出了到期时间。不过，金额、领取条件和活动时间可能调整；你自己账户页面显示到账多少、什么时候到期，才是准数。

🎁 赠金要看有效期，别一激动领完，转头放到过期。它比较像试吃券，不太适合当传家宝。

如果你的客户端没有登录领赠金入口，也不影响继续配置。可以使用自己的 DeepSeek API Key，或按下一节添加中转站。

3. 先建一个练习工作区

准备一个空文件夹，例如 DSH练习，在客户端中新建或选择这个工作区，再发一个简单任务。

如果输入框暂时不能输入，先看一下有没有选择工作区。新安装时，这一步很容易漏掉。

六、让 DSH 接入 GPT：在模型设置里完成

这一部分直接在 DSH 里配置。前面创建的中转站 Key 可以按权限使用；想单独区分两个客户端的消耗，也可以给 DSH 再建一把 Key。

1. 打开模型设置

点击用户头像，进入 设置 → 模型。

选择 添加模型提供商，再切换到 自定义模型 API。

2. 填写提供商信息

按下面这张表填写：

字段 填写内容 怎么理解
Provider ID 例如 baiyb 或 baiyb-gpt 提供商的内部标识，使用小写英文字母等允许的字符，创建后尽量保持稳定
显示名称 例如 汇枢Flow-GPT 显示在界面里的名字，自己认得就行
API 地址 https://api.baiyb.top/v1 本文 GPT Responses 路线使用的基础地址
API 协议 OpenAI Responses 与本文所选线路匹配
API 密钥 自己从中转站复制的模型 Key 不要照抄别人的截图内容

API 地址可以直接复制：

这里先认真看两眼：

  • 地址填到 /v1，不要自己再加上 /responses。
  • 协议选择 OpenAI Responses。名称里都带 OpenAI 的选项，也不能随便互换。
  • 这组地址和协议适用于本文所选线路。以后接入别的厂商，跟随对方的接入说明，不要一张表走天下。

Provider ID 创建后会被会话和默认模型引用，先起个稳妥的名字；显示名称以后可以再改。DSH 模型配置说明

3. 获取模型，创建提供商

点击 获取可用模型。正常返回后，会出现模型选择列表：

找到并勾选 gpt-6.1-sol，点击右下角的 添加所选。截图中默认勾选了多个模型；如果确实都需要，可以保留全选状态再添加，只想先跑通就留下自己要用的那一个。

确认模型已经加入表单后，再点击 创建提供商。查到模型、把模型加入表单、保存提供商，是连续的几个动作，别在最后一步提前下班。

获取到模型列表，说明模型发现这一步已经成功；具体能否正常生成回答，还需要发消息验证。

如果列表为空或探测失败，先核对地址、Key 和分组。有些端点不支持自动发现，也可以按照站内说明手动添加准确的模型 ID。

4. 回到聊天，选中刚添加的模型

点击输入框右下角的当前模型名称，再点击弹出菜单中的 模型 项：

找到刚创建的提供商，选择 gpt-6.1-sol：

为避免旧会话沿用原来的模型，第一次验证时建议新建一个聊天，再确认模型名称。

现在可以发一句简单的问题，随后去中转站使用日志里核对对应请求。回复正常、日志也能对上，这条链路才算完整跑通。

七、让它干点小活：第一次任务怎么说？

装好之后如果只问一句“你好”，多少有点像买了洗碗机，先让它洗一根筷子。当然可以，但还能试点更有意思的。

先选一个练习文件夹，试试这样的任务：

或者，给它一份自己的草稿：

把 目标、范围、输出格式 说清楚，通常比“帮我搞一下”更容易得到能用的结果。AI 还没学会读心术，至少先别拿它考这个。

八、卡住了？先查这几处

不用一报错就卸载重装。很多时候，问题只是少点了一次保存，或者多写了一截地址。

现象 优先检查
Codex 切换后还在用旧模型 CC Switch 是否真正启用了供应商；客户端是否已经完全退出并重开
DSH 添加完提供商，却仍使用 DeepSeek 是否在聊天模型选择器里切换；可以新建聊天再确认
401 / 密钥无效 Key 是否复制完整、是否多了空格、是否已被停用或过期
403 / 没有权限 令牌分组、模型权限、IP 限制，以及站点给出的具体错误信息
404 / 接口不存在 API 地址是否错误、是否重复了 /v1、协议是否选对
无可用渠道 / 模型不存在 模型 ID、令牌分组、站点当前是否提供该模型
余额或额度不足 当前供应商的账户余额与令牌额度；不要去另一个平台充值
有模型列表，但发消息失败 列表查询和模型调用是两步，继续检查协议、权限和错误详情
DSH 输入框不可用 是否选择了工作区和可用模型
Windows 商店下载卡住 商店状态、网络和代理；必要时尝试直连后重试

可以按这个顺序排查：Key → API 地址 → 模型 → 协议 → 是否保存 / 启用 → 新聊天测试 → 使用日志。

如果需要找我排查，带上出错时间、所选模型和脱敏后的错误截图会快很多。完整 API Key 就别发了，咱们查故障，不交换家门钥匙。

收工前，快速对一下

  • 我已经安装了准备使用的客户端。
  • 我清楚目前使用的是中转站，还是 DeepSeek 官方 API。
  • API 地址、Key、模型与协议是同一套配置。
  • Codex 切换后已经重启；DSH 已选中正确的提供商和模型。
  • 已发过一条测试消息，并核对对应平台的使用日志。
  • Key 已保存好，分享截图时也没有把它一起晒出去。

都打上勾，就可以拿自己的小任务试试了。先让它整理一份草稿、处理一个练习目录，熟悉之后再交更复杂的活。咱们的目标是让它帮忙干活，配置页面看看就好，不必在里面安家。
